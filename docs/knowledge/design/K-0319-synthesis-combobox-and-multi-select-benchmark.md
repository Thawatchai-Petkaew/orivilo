### What the standards say

- Kinds: select-only and editable; popup listbox, grid, tree or dialog; four autocomplete forms (K-0308).
- Keys: the combobox is in the Tab sequence and popup descendants are not; Down Arrow, Escape and Enter; optional Alt keys; Left, Right and printable keys return to an editable input; the popup "may close" when nothing matches (K-0309).
- Roles: `aria-expanded`, `aria-controls`, `aria-autocomplete`, `aria-activedescendant`, an implicit `aria-haspopup` of listbox, and `aria-busy` on a container when required owned elements are missing during loading (K-0310, K-0113).
- Multi-select list: Space toggles, `aria-multiselectable`, `aria-selected` or `aria-checked` but not both (K-0311); no interactive content in options, Select All as separate buttons (K-0312).
- Status: "5 results returned" is SC 4.1.3's example, on a search page (K-0314); waiting states are covered (K-0115); `role="status"` is a polite live region (K-0114).
- Size: SC 2.5.8 asks for 24 by 24 CSS pixels with exceptions; a combobox's dropdown list can obscure other targets, and targets in that new content are in scope (K-0315).
- Focus: SC 3.2.1, 1.4.13 and 2.4.11 for a list opened on focus (K-0316, K-0134); SC 3.2.2 and 4.1.2 for a chosen value (K-0317); SC 2.1.1 and 2.4.3 for removal (K-0318).

### Statements scoped to the pages read

- None of the Untitled UI Select, ComboBox, MultiSelect or TagSelect files read has a loading state (K-0290 to K-0293), shadcn/ui's Combobox page has no Async example (K-0299), and Radix has no combobox (K-0307). Outside those: Base UI's samples (K-0304), cmdk's Loading part (K-0302), React Aria's page, which names asynchronous loading (K-0297), and Untitled UI's Command menu, which has `filter={false}` and states no loading prop (K-0296).
- Of the Empty parts whose role was read, only Base UI's is a live region (K-0303); cmdk's has role presentation (K-0302). The role of Untitled UI's empty states was not read (K-0292, K-0296), and React Aria announces the count instead (K-0297).
- Delete on a focused tag: Base UI (K-0305) and Untitled UI's Tags page (K-0294) remove on it, and TagSelect does not (K-0293), so Untitled UI's own pages differ.
- Backspace in an empty input: Base UI removes the last chip at once (K-0305); Untitled UI's TagSelect and InputTags move to a tag without removing it (K-0293, K-0295). No APG line settles it (K-0313).
- No APG pattern covers tags or a multi-value combobox (K-0313); the nearest written removal is the Rearrangeable listbox example, a two-list control (K-0312).
- Of the WCAG Understanding pages read, three use the word combobox: SC 2.4.11 ("combobox lists", K-0316), SC 2.5.8 (a dropdown list of suggestions, K-0315) and SC 4.1.2 (custom widgets, K-0317). The pages for 4.1.3, 3.2.1, 1.4.13, 3.2.2, 2.1.1 and 2.4.3 do not (K-0314, K-0316, K-0317, K-0318), so applying them here is our reading.
