### Standards, each scoped to the pages read

- SC 4.1.3 (AA) names the waiting state of an application as a status message (K-0115). Its Understanding page counts "Searching...", "18 results returned" and "No results returned" as status updates when they take no focus and cause no page refresh, and leaves the list of results itself out (K-0178).
- The same page says the criterion does not force authors to generate new status messages (K-0178).
- ARIA22's test puts `role="status"` on the container before the message occurs; the tool found no zero-result or loading example on that page (K-0178).
- `role="status"` is polite and atomic by default (K-0114); `aria-busy` asks assistive technologies to wait and does not announce (K-0113).
- WAI-ARIA 1.2 joins a region, `aria-busy` and `aria-describedby` for a progressbar showing that region's loading (K-0179). APG Feed warns that `aria-busy` left true can hide changes from some users (K-0180).
- WAI-ARIA 1.2 says no more than one `main` role, as a SHOULD (K-0181); WHATWG HTML says no more than one `main` element without `hidden`, as a must (K-0182); ARIA in HTML lists no other role for `main` (K-0183).
- The WCAG, ARIA22 and Feed pages read name no empty board and no first-use state (K-0178, K-0180).

### Statements scoped to the files read

- Neither publisher's empty component sets a status role in the files read (K-0172, K-0175); the announcement in shadcn's loading example comes from the Spinner (K-0176).
- Both publishers keep the action in its own slot: `Footer` (K-0171) and `EmptyContent` (K-0174).
