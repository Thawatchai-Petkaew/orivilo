### What the standards say

- File inputs: `input type=file` has no role and may carry `aria-invalid` and `aria-required` (K-0285). `accept` is a hint (K-0286). The APG has no file input or drag pattern (K-0282).
- Dragging alternatives: SC 2.5.7 (AA) asks for a single pointer route without dragging and is judged apart from keyboard (K-0275). SC 2.1.1 (A) asks for keyboard operation, and its example pairs drag and drop with cut and paste or form controls (K-0276). The ARIA drag attributes are deprecated (K-0284).
- Status messages: SC 4.1.3 (AA) covers progress and errors (K-0115, K-0277). ARIA25 puts file upload progress in a polite live region, since role progressbar is not one (K-0278). Role status is polite and takes no focus (K-0114).
- Error identification: SC 3.3.1 (A) needs the item and the error in text (K-0279). SC 3.3.3 (AA) needs known corrections (K-0280). SC 3.3.2 (A) covers instructions on allowed input (K-0281).

### Statements scoped to the pages read

- Of Untitled UI, shadcn/ui and Radix, only Untitled UI ships a drop target (K-0264); shadcn/ui and Radix ship none (K-0267, K-0272). The exception outside the three is React Aria's DropZone (K-0287).
- None of the three gives the drag itself a keyboard or screen reader route in what was read. Their non-drag routes are Untitled UI's input and button (K-0264) and shadcn/ui's native input (K-0267); Radix has no file part (K-0272).
- Neither list item read sets a live region in its source (K-0264, K-0270); a caller can add one to Attachment through spread props (K-0270).
- Of the bars read, Untitled UI's `ProgressBar` and Radix `Progress` set no name (K-0265, K-0273). shadcn/ui's Label example markup was cut off, so it is not counted (K-0271).
- No prop read sets a maximum file count: Untitled UI has `allowsMultiple` only (K-0263), and shadcn/ui's Attachment and Radix Progress have no limit prop (K-0268, K-0273).
- Of the three, only shadcn/ui's docs ask for the failure reason in text (K-0270). Untitled UI shows fixed text (K-0262); Radix has no failure state (K-0273).
- Of the WCAG pages read, only ARIA25 and ARIA27 use a file upload as their case (K-0278). K-0275, K-0277 and K-0279 state the absence; K-0276, K-0280 and K-0281 show no file example in what the fetch returned.

### Open points

- ADR 0009 point 5 says 4 MB without saying 1,000 or 1,024 based. Untitled UI's text uses 1024 (K-0261).
- Point 5 bounds images leaving the server. Where a sixth file is stopped, and what the person sees, is in no source read (K-0263 has no count limit).
- `.claude/rules/design-system.md` says a shared component is built on a shadcn primitive and behaviour comes from `radix-ui`; the sources give only `Input type="file"` and Attachment, with no picking or drop primitive (K-0267, K-0272).
- `Field`'s `children` comment names Input, Textarea or Select, not a file control.
- `SavedStudio.tsx` hides its input with `aria-hidden` and `tabIndex={-1}` behind a Button; Untitled UI's zone leaves the input in the tab order, and `FileTrigger` uses `display: none`. MDN's note on hiding an input is about a label-and-input pattern (K-0264, K-0266, K-0286). The sources do not rank these.
- Whether a file dragged in from the operating system is in SC 2.5.7's scope (K-0275).
- How often to announce progress: ARIA25 does not say (K-0278).
