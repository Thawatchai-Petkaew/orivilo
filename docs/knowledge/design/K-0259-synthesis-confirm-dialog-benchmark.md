### What the standards say

- Role: alertdialog holds the alert message and the rest of the dialog, needs a name, should be modal and should reference its message with `aria-describedby` (K-0250); APG names action confirmation prompts as a use and adds `aria-modal` true (K-0251). Radix hides the rest with `hideOthers` and sets no `aria-modal` (K-0249).
- First focus: ARIA 1.2 says an active element, "such as a form control or confirmation button" (K-0250). APG says it may be advisable to focus the least destructive action on a step that is not easily reversible, the most used element when the dialog only informs or continues, and a static element for structured or long content (K-0252); its worked example focuses No (K-0253). WCAG's example says only "within the dialog" (K-0258).
- Close: focus returns to the invoker unless it is gone or the work flow makes another target more logical (K-0252); WCAG's example says the button or the element following it (K-0258).
- Error prevention: SC 3.3.4 (AA) covers deleting user-controllable data and takes any one of reversible, checked or confirmed (K-0254). SC 3.3.6 (AAA) takes the same three for every submission (K-0255). G168 is the confirm technique and G99 the recovery one (K-0256).
- Messages: SC 3.3.1 and 3.3.3 are about input errors (K-0257); SC 4.1.3 covers how a status is exposed (K-0115).

### Statements scoped to the pages read

- Of the implementations read, only Radix Alert Dialog fixes first focus on Cancel (K-0247). Base UI uses the first tabbable element (K-0245). Our Dialog and Radix Dialog use the first tabbable non-link (K-0249). Untitled and React Aria state no first target (K-0237, K-0242).
- None of the outside dialogs read has a pending or failure prop (K-0237, K-0238, K-0243, K-0245, K-0246, K-0248). Two things sit nearby: Untitled's Button has `isLoading` (K-0240), and Radix's docs show an async close with no pending display (K-0248). Untitled's PRO examples were not read, so they are unknown, not absent (K-0238), and React Aria's Modal page was read for role, dismissal and focus only (K-0242).
- Outside press does not close the Radix alert dialog (K-0247) or an Untitled modal by default (K-0237). Our Dialog closes on it unless pending. Base UI's behaviour was not read (K-0245).
- No page read names accepting AI changes; the nearest texts are the APG note on dialogs that continue processing (K-0252) and SC 3.3.6 (K-0255, where the reading is ours).

### Open points

- ARIA 1.2 gives a confirmation button as an example of a focus target (K-0250), and APG advises the least destructive action (K-0252, K-0253). The two are recorded, not reconciled.
- `docs/specs/ORV-64/audit.md` A.2 says Untitled has no ConfirmDialog; K-0238 and K-0239 show confirmation versions of its modals.
- Our `pending` sets `aria-busy` on the panel, and the loading Button's status line sits inside it; K-0113 says assistive technologies may wait for or ignore changes while it is true. Not tested here.
- APG's example keeps disabled buttons in the Tab sequence with `aria-disabled` (K-0253). Our examples use `disabled` on cancel and close, which FocusScope skips (K-0249), and `aria-disabled` on the loading confirm.
- Escape during pending: APG says Escape closes (K-0252), Radix leaves it live (K-0247), Untitled offers a switch (K-0237), and ours blocks it. No source read speaks of a pending dialog.
- Where focus goes after a failed confirm, and whether a failed server action is an input error (K-0257): no source read states either.

### Not read

- Untitled's four PRO examples, their four previews (two returned no body, two were not tried) and its API table (K-0237, K-0238).
- The React Aria destructive dialog example; `https://react-aria.adobe.com/Dialog` returned 404 (K-0242).
- shadcn/ui's React Aria version and Base UI's `useRenderDialogRoot` (K-0245).
