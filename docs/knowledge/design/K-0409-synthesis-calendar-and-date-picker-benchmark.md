### Keys, as read

- Arrows: the APG moves by day and week (K-0400); DayPicker does too, with Shift for month or year (K-0397); React Aria has the handlers, whose bodies were not read (K-0387).
- Home and End: the APG uses the first and last day of the current week (K-0400); DayPicker the start and end of the week (K-0397); React Aria the first and last day of the focused month in a month view (K-0387).
- Page keys: month, and year with Shift, in the three sources (K-0400, K-0397, K-0387).
- Enter and Space: the APG selects and closes (K-0400); DayPicker's docs say "Select the focused day.", through a native button by our reading (K-0397); React Aria calls `selectFocusedDate` (K-0387).
- Esc: the APG closes (K-0400); DayPicker's key map has no entry (K-0397), so by our reading it falls to the wrapper, and our Popover closes on Escape (K-0130, `popover.yaml`); React Aria clears a range anchor and returns false (K-0387).
- The APG Grid page's Control + Home and Control + End (K-0402) are not in the date example's rows read (K-0400).

### Thai year

- Data: CLDR lists Buddhist then Gregorian for Thailand and UTS 35 calls the first the default (K-0405); ECMA-402 takes a locale's first element as its default (K-0404).
- Output: `th-u-ca-buddhist` shows 2563 and `th-u-ca-gregory` shows 2020 for one date, from ICU output in a 2020 message (K-0406).
- Runtime: a 2015 Android patch forced Gregorian, and one project reports Android showing 2026 (K-0406). No plain `th-TH` output was read and nothing was run.
- Fixing it in code: `th-TH-u-ca-buddhist` or `{ calendar: "buddhist" }`, and `-u-ca-gregory` the other way (K-0404, K-0406). `LOCALE_TAGS.th` is `th-TH` (`locale.ts`).
- Era word: CLDR's Thai Buddhist patterns carry พ.ศ. in the full date and the year-only form, not in the long, medium or short date (K-0405).
- Digits: CLDR defaults Thai to Latin digits (K-0405); DayPicker's Buddhist build defaults to Thai digits (K-0398).
- React Aria: shows the calendar `DateFormatter` resolves, keeps `onChange` in the value's calendar or Gregorian (K-0388).
- DayPicker: `@daypicker/buddhist` 10.0.2 adds 543 for listed format strings only; months and weeks stay Gregorian (K-0398).
- date-fns: the Thai localize file has no 543 and no พ.ศ. (K-0408), so a year stays Gregorian by our reading.

### Week start

- CLDR gives Thailand and the United States Sunday (K-0407), so both ORIVILO locales start on Sunday in that data.
- date-fns's Thai locale is Sunday, `firstWeekContainsDate` 1 (K-0408); DayPicker reads it from the locale unless `weekStartsOn` is set (K-0399).
- React Aria takes `firstDayOfWeek`, then `getWeekInfo` where present, then its table, where a missing region is Sunday (K-0388).
- `Intl.Locale.getWeekInfo()` is Baseline 2026, newly available since July 2026 (K-0407), so a runtime read needs a fallback.

### Statements scoped to the pages read

- Of the two libraries, Untitled UI's picker file has an Apply and Cancel footer (K-0381); shadcn's samples read (basic, range, date of birth, input, calendar presets) show none (K-0391, K-0392). Its Time Picker sample was not read.
- Untitled UI's Date pickers page and shadcn's Calendar and Date Picker pages have no accessibility section (K-0380, K-0389, K-0391). The keyboard behaviour they rely on is documented by DayPicker (K-0397) and read in React Aria's source (K-0387).
- No page or file read here shows a typed Buddhist year being parsed back to a date (K-0392, K-0398, K-0401). The date input in Untitled's default Calendar row (K-0383) was not read on this point.
- React Aria's `onChange` keeps the calendar of the value it holds, or Gregorian when none is given (K-0388); DayPicker's Buddhist build keeps Gregorian months and weeks and changes the displayed year for listed formats (K-0398). Neither source shows a Buddhist value being stored by default.

### Open points

- Owner: which year Thai UI shows, with or without พ.ศ., and in which digits (audit D.3 row 28). The sources read set out the options; none decides it, and nothing was run here.
- Engine: `radix-ui` has no calendar (K-0394) while `.claude/rules/design-system.md` takes behaviour from it, so a calendar brings either DayPicker (K-0394, K-0398) or React Aria (K-0386). That is a call for the architect and the owner.
- Major version: shadcn's site declares ^9.7.0, its registry installs `@latest`, now 10.0.2, and the Buddhist route differs between them (K-0393, K-0398).
- Non-modal Popover against the APG's modal example: `aria-modal`, Tab wrapping and outside clicks differ (K-0130, K-0403).
- Commit model: on select, or Apply and Cancel (K-0381, K-0392, K-0400).
- Home and End: by week or by month (K-0387, K-0397, K-0400).
- A typed Thai year: which year a text field accepts, and how the hint says so (K-0401).
- A run of `th-TH` and of the chosen tag on our Node and browser targets (K-0406).
- Thai digits differ between sources (K-0398, K-0405). The Thai label wording in DayPicker's locale file (K-0399) was recorded as returned and not checked by a Thai reader.
