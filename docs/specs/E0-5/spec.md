## Why

The backlog's done-when for E0-5: a script computes every text and UI pair from the token JSON, and failing pairs fail CI. Until now only the pairs someone remembered to declare in `semantic.json` were checked (26 of them), plus the recipe pairs in `pairs.ts`. A new surface, a profile override or a dark value could leave text unreadable with no test noticing, and DESIGN.md §12 carried the dark `surface.selected` and feedback values as placeholders "until E0-5 computes them". The design gate (§11) asks for script output on the real pairs; there was no script.

## Story

As the owner reviewing a token or profile change, I want one command that computes every pair the semantic layer puts together under the neutral set and every profile in both modes, prints the ratios and fails when any pair is under its floor or any colour is unexplained, so that contrast is a check that runs, not a column someone fills in.

## Rules and bounds

- **One source.** `contrast-pairs.ts` derives the pairs; the script, the test and (later) the Foundations pages read it. The per-pair loops that `tokens.test.ts` and `profiles.test.ts` carried are removed, not duplicated.
- **Floors.** WCAG 2.2: 4.5 for text (1.4.3), 3.0 for a boundary that identifies a control (1.4.11). No large-text allowance; the type scale's smallest sizes decide.
- **What is not a pair.** A tint under text (hover, selected, sunken, raised, selection, feedback surfaces) is checked through the text on it, not as a boundary. A hover or press button background is checked through its label. Disabled text, disabled surfaces and disabled edges are exempt (inactive components). Dividers and card edges are decorative. The lime intent action and the signature bead are identity, checked through their text. Each of these is written down, in `EXEMPT` or in the module comment, so the choice is reviewable.
- **Recipe pairs stay.** `pairs.ts` checks component-token slots (what a recipe actually draws); this story checks the semantic contract underneath. Both run.
- **Lane S, one value change.** The profiles' dark `text.secondary` is the only value that moves; the base contract does not change. The profile layer is the profile story's to change (DESIGN.md §5); this is recorded in the DESIGN.md changelog with its impact.

## Out of scope

Large-text floors by type size, APCA, computing values automatically (the check reports, people choose values), a Storybook page listing the matrix (the Foundations pages keep showing the declared ratios), an E0-4 report file.
