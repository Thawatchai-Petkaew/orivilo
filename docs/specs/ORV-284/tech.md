## 4. The counted cost (`byok-cost-1`, PR 2)

### 4.1 The fields read, and how sure we are of each

All from K-0412 (OpenRouter's own docs, company-reported, confidence 0.75), on the non-streaming chat completions answer:

| Field                                                                                      | Type in the schema | Meaning, as the docs give it                                                                                                                                                            | Required                            |
| ------------------------------------------------------------------------------------------ | ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------- |
| `usage.cost`                                                                               | number or null     | "The total amount charged to your account" (usage accounting guide); "Cost in credits"                                                                                                  | No                                  |
| `usage.is_byok`                                                                            | boolean            | "Whether a request was made using a Bring Your Own Key configuration" (chat completions reference)                                                                                      | No                                  |
| `usage.cost_details.upstream_inference_cost`                                               | number or null     | "The actual cost charged by the upstream AI provider" (usage accounting guide); "only available for BYOK" requests, "0 or null" for all others (same guide, on the generation endpoint) | No                                  |
| `usage.cost_details.upstream_inference_prompt_cost`, `upstream_inference_completions_cost` | numbers            | The split of the upstream cost on Chat Completions (usage accounting guide)                                                                                                             | Yes, when `cost_details` is present |

What K-0412 records as **not stated**: which amount `usage.cost` holds on a request through the owner's key, and what `is_byok` reads on a request that fell back to shared capacity. Its reading, labelled ours: on such a request `usage.cost` holds only OpenRouter's fee (0 inside the plan's allowance), and the provider's charge sits in `upstream_inference_cost`. Its sample of a request on OpenRouter's capacity: `cost` 0.0012, `is_byok` false, `upstream_inference_cost` null, prompt 0.0008 and completions 0.0004, so on such a request the split is the parts of `cost`, not an amount beside it.

### 4.2 Telling a request through the owner's key apart

`usage.is_byok`, read strictly:

- `true`: through the owner's key;
- `false`: on OpenRouter's capacity, counted as today;
- absent, null, or not a boolean (`"true"`, `1`): cannot tell, so not reported.

No other signal is used. The provider name, the model id and the price are not evidence of who paid. The generation endpoint's `is_byok` would need a second call per request (open question 7 (c), out of scope).

**What this changes today.** An answer with `usage.cost` and no `is_byok` counts today and records null after PR 2, because such an answer could be a request through the owner's key whose `usage.cost` holds only the fee. K-0412's sample carries `is_byok`; row 9 must confirm a real answer does (§4.5, point 1). Until it does, PR 2 does not merge.

### 4.3 The counted amount

`reportedCostMicroUsd(body: unknown): number | null` keeps its signature and its one caller (`openRouterComplete`, which passes the result to `onCall` and from there to `recordUsage`). Its result, read from `body.usage` (`u`) and `u.cost_details` (`d`):

| Case | `u.is_byok`   | Counted (millionths of a US dollar)                                                                                                                                                                         | Why it never counts less and never counts twice                                                                                                                                                                                                                                                                                                    |
| ---- | ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| C1   | `false`       | `toMicroUsd(u.cost)` when `u.cost` is a number that `toMicroUsd` accepts; else null                                                                                                                         | `usage.cost` is the total charged to OpenRouter credits, and no provider account was charged. The `d` parts are inside it (K-0412 sample), so adding them would count twice                                                                                                                                                                        |
| C2   | `true`        | `sumToMicroUsd([u.cost, d.upstream_inference_cost])` when `u.cost` is a number at or above 0, `d.upstream_inference_cost` is a number above 0, and `u.cost` is below `d.upstream_inference_cost`; else null | The fee and the provider's charge are two charges to two accounts; both are counted once. The guard `u.cost < upstream` holds when `u.cost` is the fee (5 percent of the OpenRouter price, or 0) and fails when `u.cost` already holds the provider's charge, so a reading K-0412 did not expect records null instead of counting the charge twice |
| C3   | anything else | null                                                                                                                                                                                                        | Cannot tell who paid, so no part can be counted without risking less or twice                                                                                                                                                                                                                                                                      |

Each null is the existing "not reported" route: `onCall` gets `{ costMicroUsd: null }`, `recordUsage` writes one `ai-usage` step line `cost-not-reported` (ORV-121 `spend-cap-6`), and the record holds null. Nothing new is added to `apps/web`.

Notes on C2:

- **A provider charge of 0** on a request through the owner's key records null. The guide gives "0 or null" as the value of a request that is not BYOK, so a 0 here is read as "not given", not as a free call. A request on a paid model is never free.
- **The split is not read.** If `upstream_inference_cost` is missing and only the split is given, C2 records null until row 9 shows that form (§4.5, point 4).
- **`server_tool_cost` is not read.** Our body names no server tool (`openRouterBody` has no `tools` and no `plugins`), so none is billed. Row 9 records it (§4.5, point 7).
- **Overshoot.** ORV-121's bound stands. Until PR 2 ships, a request through the owner's key adds `usage.cost` only (the spec's "Rules and bounds", Overshoot).

### 4.4 Rounding (`sumToMicroUsd`, new in `money.ts`)

```ts
/** The exact sum of `usd`, rounded once to millionths, half to even. Null when any value is not one `toMicroUsd` accepts. */
export function sumToMicroUsd(usd: readonly number[]): number | null;
```

- Each value is parsed from its shortest decimal text by the pattern `toMicroUsd` uses (`TEXT`), into a `bigint` at a common scale; the values are added as `bigint`; the sum is rounded once, half to even, at the millionth; null past `Number.MAX_SAFE_INTEGER`, for a negative or non-finite value, and for an empty list.
- `toMicroUsd(x)` becomes `sumToMicroUsd([x])`, so ADR 0015 decision 12's one rounding helper stays one rule. Its tests (`money.test.ts`, worked example 2 of ORV-121, `14000 12 14 13 5000000`) stay green unchanged.
- Rounding each part and adding could lose up to one millionth on a request (two half-millionths rounded down); rounding the exact sum once loses at most half a millionth, the same as a single `usage.cost` today. That half-millionth is decision 12's rounding, not an under-count of this design.

### 4.6 If row 9 cannot settle it

Open question 7, default (b): the owner pauses the key in OpenRouter, so requests run on credits and C1 counts them as today; a follow-up story designs a look-up through the generation endpoint (option (c)). PR 2 then ships C1 and C3 only if the owner so decides, as a further addition to ADR 0009.

### 4.7 Options not chosen

- **`usage.cost` alone** (today). Under K-0412's reading it counts only the fee, possibly 0 (the spec's W2).
- **`max(usage.cost, upstream_inference_cost)`.** Never counts twice but misses the fee.
- **`usage.cost` plus `upstream_inference_cost` on every answer.** Counts twice wherever the provider's charge is already inside `usage.cost`, and K-0412's generation sample shows a non-null upstream cost on a request that is not BYOK.
- **Treat a missing `is_byok` as false.** Keeps today's count for answers without the field, but a request through the owner's key without it would count the fee only. The boundary is "when it cannot tell, it records not reported".
- **The generation endpoint per request.** A second call, a delay K-0091 does not state, and a job to run it: open question 7 (c), a later story.

## 8. The probe of row 9 (`real-call-1`, PR 2 task 2.1)

`scripts/probe/openrouter-byok-probe.mjs`, run by hand, outside turbo and outside `pnpm test`, in the form of the `interpret` recorder (ADR 0009 addition of 2026-10-30):

- **One request, the same as `interpret`'s.** It loads the engine through `ts-resolve-hook.mjs` and calls `interpretBrief(llmInterpreter(AI_MODELS.interpret, openRouterComplete(...)), { text: BRIEF })` once, so the body is `openRouterBody`'s with zero retention on. `BRIEF` is one ordinary English brief in the script, written for the run, with no personal data (for example "A small bakery in Chiang Mai that sells sourdough to cafes; the brand should feel warm and careful.").
- **The bound.** One call, no retry, `AbortSignal.timeout(20_000)`.
- **The key** comes only from `process.env.OPENROUTER_API_KEY`, through `--env-file=.env.recorder`. Without it the script prints one line and exits 1 before any request.
- **What it keeps.** It passes `openRouterComplete` a `fetch` that calls the real `fetch`, reads `response.clone()` as text, and keeps it. After the call (whatever its outcome) it parses that text and prints one JSON line: `{ status, model, provider, usage, costMicroUsdToday }`, where `usage` is the answer's `usage` with only key names and number, boolean or null leaves kept (strings and arrays dropped), `provider` is kept only when a string, and `costMicroUsdToday` is what `onCall` received. It never prints `choices`, the brief, the key, headers or the answer's `id`.
- **Its test** (`scripts/openrouter-byok-probe.test.mjs`, under `pnpm test:scripts`) runs the exported `probe({ env, fetch, write })` with a fake `fetch` and a stand-in key. It must fail on: a second request (count is 1, also when the fake answers 429); no abort signal on the request; a printed line holding the answer's content, the brief or the stand-in key; a string leaf from `usage` printed; a request sent without a key.
