# ORV-121 tech notes: the AI usage record and the spend cap per workspace

This turns the spec's "Rules and bounds" (`spend-cap-1` to `spend-cap-8`) into a design a builder can follow. It was checked against ADR 0002 (server-only access, restricted role, row security by workspace), ADR 0009 (points 3, 7 and 8, the `interpret` price), ADR 0015 decisions 4, 7 and 12, ADR 0018 decisions 4, 5 and 7, K-0091 (where OpenRouter reports the cost of a chat completion), the ORV-112 tech notes (the shared store, the 2 second bound, the Bangkok offset), `.claude/rules/security.md`, and the code at `a9a250e`: `apps/web/app/directions/actions.ts`, `read-outcome.ts`, `packages/intent-engine/src/openrouter.ts`, `llm-interpreter.ts`, `packages/auth/src/access.ts`, `rate-limit.ts`, `packages/db/src/client.ts`, `schema/` and `migrations/` (last: `0005_rate_limits_access`).

POC mode: this note covers the contract only.

## 1. Decisions this design rests on

ORV-121 comment 10258, under the owner's delegation (ADR 0012 decision 4, POC mode of ORV-137): lane L, POC mode, and the spec's four defaults (the cap per workspace per calendar month in US dollars from OpenRouter's reported usage; over the cap the job is not called and the rules' reading is kept and labelled; `AI_SPEND_CAP` with `retryable: false` where no fallback exists; the cap figure an open question with a default). Each of the spec's eight open questions takes its default:

| Open question             | Default taken                                         | Where this note uses it |
| ------------------------- | ----------------------------------------------------- | ----------------------- |
| 1. The cap figure         | 5 US dollars, `AI_SPEND_CAP_MICRO_USD = 5_000_000`    | §4                      |
| 2. The integer unit       | Millionths of a US dollar, half to even               | §2, §3, ADR 0015        |
| 3. No reported cost       | Recorded as not reported (null), adds nothing         | §2, §3                  |
| 4. Record write fails     | Keep the reading, log the error name only             | §5                      |
| 5. When AI comes back     | "When the new month starts", no date                  | §5 (C1 as written)      |
| 6. One cap or one per job | One cap over every job; each record names its job     | §2, §4                  |
| 7. Size                   | One PR; the builder splits as the spec says past ~400 | §8                      |
| 8. Where the cost is      | K-0091: `usage.cost` on the chat completion, no flag  | §3                      |

## 2. The table `ai_usage`

One row per request the server sends to OpenRouter for an AI job (`spend-cap-1`). Two migration files, as the repo pairs them (`0004_rate_limits` + `0005_rate_limits_access`):

- `packages/db/migrations/0006_ai_usage.sql`, generated by `drizzle-kit generate` from the schema file below. Commit what drizzle-kit writes; do not hand-edit it.
- `packages/db/migrations/0007_ai_usage_access.sql`, made by `drizzle-kit generate --custom --name ai_usage_access`, holding the grant, row security, policy and revokes.

Each comes with its `meta/*_snapshot.json` and a `_journal.json` entry. If another branch lands `0006` first, regenerate on top of it; the numbers are not part of the contract.

### Schema file `packages/db/src/schema/ai-usage.ts`, exported from `schema/index.ts`

```ts
import { sql } from "drizzle-orm";
import { bigint, check, index, pgTable, text, timestamp } from "drizzle-orm/pg-core";
import { organization } from "./auth.ts";

/**
 * One row per request the server sent to OpenRouter (ORV-121). Workspace data: written and read
 * only through the spend cap helper in @orivilo/auth, inside `inWorkspace`. The app role may insert
 * and select, never update or delete (migration 0007). Holds no brief, prompt, answer, email or IP.
 */
export const aiUsage = pgTable(
  "ai_usage",
  {
    id: text("id").primaryKey(),
    workspaceId: text("workspace_id")
      .notNull()
      .references(() => organization.id, { onDelete: "cascade" }),
    // A plain id, not a foreign key: a record keeps who spent after they leave (as direction_version).
    userId: text("user_id").notNull(),
    job: text("job").notNull(),
    model: text("model").notNull(),
    /** Millionths of a US dollar (ADR 0015 decision 12, addition of 2026-10-29); null = not reported. */
    costMicroUsd: bigint("cost_micro_usd", { mode: "number" }),
    currency: text("currency").notNull().default("USD"),
    createdAt: timestamp("created_at", { withTimezone: true, mode: "date" }).notNull(),
  },
  (t) => [
    index("ai_usage_workspace_created_idx").on(t.workspaceId, t.createdAt),
    check("ai_usage_job_check", sql`char_length(${t.job}) between 1 and 40`),
    check("ai_usage_model_check", sql`char_length(${t.model}) between 1 and 200`),
    check("ai_usage_cost_check", sql`${t.costMicroUsd} >= 0`),
    check("ai_usage_currency_check", sql`${t.currency} = 'USD'`),
  ],
);
```

| Column           | Type                                            | Null | Holds                                                                                                                |
| ---------------- | ----------------------------------------------- | ---- | -------------------------------------------------------------------------------------------------------------------- |
| `id`             | `text`, primary key                             | no   | `crypto.randomUUID()`, made by the helper                                                                            |
| `workspace_id`   | `text`, references `organization(id)`, cascade  | no   | The workspace from `withWorkspace`'s `Access`, never from the client (`spend-cap-5`)                                 |
| `user_id`        | `text`                                          | no   | Better Auth's user id from `Access`                                                                                  |
| `job`            | `text`, 1 to 40 characters                      | no   | A key of `AI_MODELS` (`AiJob`), checked by the type; text so a new job needs no migration                            |
| `model`          | `text`, 1 to 200 characters                     | no   | The pinned id the request named (`AI_MODELS[job]`), not the answer's `model`, which may carry a dated suffix         |
| `cost_micro_usd` | `bigint` (`mode: "number"`), `>= 0`             | yes  | The reported cost in millionths of a US dollar (§3); `null` when none was reported, never 0 (`spend-cap-6`)          |
| `currency`       | `text`, default and check `'USD'`               | no   | The ISO 4217 code beside the amount (ADR 0015 decision 12)                                                           |
| `created_at`     | `timestamp with time zone`, no database default | no   | The server clock when the helper writes the row (`deps.now`), so tests inject it and the month follows `spend-cap-2` |

- **The one index** is (`workspace_id`, `created_at`). The month's sum is a range scan on it, and it leads with `workspace_id`, so it also serves the cascade from `organization`.
- **No float anywhere.** `mode: "number"` reads the `bigint` as a JS number; the helper checks every amount with `Number.isSafeInteger` before it writes (ADR 0015 decision 12). The largest safe value is about 9 billion US dollars in millionths.
- **No pruning** (spec, "Out of scope"). A row is about 150 bytes; at the `ai-read` day limit of 50 per person, a workspace of 10 writes at most 15,500 rows a month.
- **Classification tags**, when `classification.ts` lands (ORV-113): `user_id` `personal` (it names a person through `user`), every other column `internal`.
- `TENANT_TABLES` in `schema/workspace.ts` gains `"ai_usage"`, so the existing policy test covers it.
- `packages/db/src/index.ts` adds `gte` and `lt` to its operator exports, for the month range.

### Custom `0007_ai_usage_access.sql`

```sql
-- ORV-121: AI usage records are workspace data (ADR 0002). The app role inserts and reads rows of
-- the workspace the helper set; it may not change or delete a record.
GRANT SELECT, INSERT ON "ai_usage" TO orivilo_app;
--> statement-breakpoint
ALTER TABLE "ai_usage" ENABLE ROW LEVEL SECURITY;
--> statement-breakpoint
CREATE POLICY "workspace_rows" ON "ai_usage" TO orivilo_app
  USING (workspace_id = current_setting('app.workspace_id', true))
  WITH CHECK (workspace_id = current_setting('app.workspace_id', true));
--> statement-breakpoint
-- Nothing for any other role, whatever default privileges the host applies to new tables.
REVOKE ALL ON "ai_usage" FROM PUBLIC;
--> statement-breakpoint
DO $$
DECLARE r text;
BEGIN
  FOREACH r IN ARRAY ARRAY['anon', 'authenticated', 'service_role'] LOOP
    IF EXISTS (SELECT FROM pg_roles WHERE rolname = r) THEN
      EXECUTE format('REVOKE ALL ON "ai_usage" FROM %I', r);
    END IF;
  END LOOP;
END
$$;
```

- **Update and delete are refused by the grant**, not by a policy: `orivilo_app` holds no `UPDATE` or `DELETE`, so either statement fails with a permission error before row security is read. The policy is `FOR ALL` with the same `USING` text as the other tenant tables, so the existing "limits every tenant table" test matches it.
- **Deleting a workspace** cascades to its records. Postgres runs a foreign key's cascade as the owner of the referencing table, so the app role needs no `DELETE` for it. That is read from Postgres' behaviour, not from a knowledge entry, so a test proves it (§9, row 13): if it fails, the builder stops and reports, and the cascade becomes a decision.

## 3. The reported cost (K-0091)

- **The field.** `usage.cost` of a non-streaming chat completion answer, a number or null, in credits with a US dollar base; sent with no request flag (K-0091). The request body does not change.
- **Read only from a 200 answer.** An error status, a rejected `fetch` (timeout, abort, network) or a body that cannot be parsed has no cost: not reported. A 200 answer whose `usage` is missing, whose `cost` is missing or `null`, or whose `cost` is not a finite number at or above 0, is not reported. K-0091 records that the schema allows a missing or null cost with no documented meaning, which is why none of these becomes 0. A reported `0` is a reported value and is stored as 0.
- **Read before anything else is checked.** The cost is read right after the 200 body is parsed, before the model check and before the text is taken, so an answer refused later (another model, no text, not JSON, outside `llmAnswerSchema`, a quote not in the brief) still carries its cost (`spend-cap-1`, row 6).
- **To an integer.** `toMicroUsd(usd)` (§7, clause S3) rounds half to even at the millionth from the shortest decimal text of the number (`String(usd)`, with an exponent form such as `5e-7` written out), never by multiplying the float. `response.json()` has already parsed the number, so that text is the closest the server has to OpenRouter's own digits; they differ only past a double's precision. The spec's worked example 2 gives `14000 12 14 13 5000000`; the halves 0.5, 1.5 and 2.5 millionths give 0, 2 and 2. A result that is not a safe integer is not reported.
- **Not used: the generation endpoint** (`GET /api/v1/generation`, K-0091). It is a second request per call, and no OpenRouter page states when its answer is ready. The spec's open question 3 rejected the later lookup (option c) for that reason.

## 4. The spend cap helper (`packages/auth/src/spend-cap.ts`)

It sits in `packages/auth`, the only package allowed to import `@orivilo/db/client` (ADR 0002), and reaches the table only through `withWorkspace`.

```ts
import type { AiJob } from "@orivilo/intent-engine";
import type { AccessDeps } from "./access.ts";

/** One cap for every workspace, over every AI job together (ORV-121 open questions 1 and 6). */
export const AI_SPEND_CAP_MICRO_USD = 5_000_000; // 5 US dollars

export interface SpendCapDeps {
  access: AccessDeps;
  now?: () => number; // ms since epoch; default Date.now
  timeoutMs?: number; // default 2_000 (spend-cap-6, the ORV-112 bound)
  capMicroUsd?: number; // default AI_SPEND_CAP_MICRO_USD; set only by tests
}

/** Who a call is charged to, as the authorization helper resolved it. */
export interface Charge {
  workspaceId: string;
  userId: string;
}

export type SpendCheck =
  | { ok: true; charge: Charge }
  | { ok: false; reason: "capped" }
  | { ok: false; reason: "unavailable" }; // the sum could not be read in time: fail closed

export interface UsageEntry {
  job: AiJob;
  model: string;
  costMicroUsd: number | null; // null = not reported
}

export interface SpendCap {
  /** Throws `Denied` without an active workspace or for a non-member; never throws otherwise. */
  check(headers: Headers, workspaceId: string | null | undefined): Promise<SpendCheck>;
  /** One row per entry, in one transaction; nothing to do for no entries. Throws on any failure. */
  record(headers: Headers, charge: Charge, entries: readonly UsageEntry[]): Promise<void>;
}

export function createSpendCap(deps: SpendCapDeps): SpendCap;

/** The Bangkok calendar month holding `nowMs`: start inclusive, end exclusive (spend-cap-2). */
export function monthOf(nowMs: number): { start: Date; end: Date };
```

### `monthOf`

With `B = BANGKOK_OFFSET_SECONDS * 1000` (from `rate-limit.ts`): take `d = new Date(nowMs + B)`, then `start = Date.UTC(d.getUTCFullYear(), d.getUTCMonth(), 1) - B` and `end = Date.UTC(year, month + 1, 1) - B`. This is the spec's worked example 1: `2026-10-31T16:59:59Z` falls in `2026-09-30T17:00:00.000Z` to `2026-10-31T17:00:00.000Z`, and `2026-10-31T17:00:00Z` in `2026-10-31T17:00:00.000Z` to `2026-11-30T17:00:00.000Z`. `Date.UTC` rolls month 12 into January of the next year.

### `check`

1. Start a `timeoutMs` timer that sets `timedOut` and settles the call as `unavailable`.
2. `withWorkspace(deps.access, headers, workspaceId, "member", fn)`. The workspace id is the one `run` passes, the session's `activeOrganizationId` (`spend-cap-5`); `withWorkspace` reads the session again from the same headers and checks membership before any workspace query.
3. In `fn`, first `SELECT set_config('statement_timeout', ms, true), set_config('lock_timeout', ms, true)`, as the ORV-112 limiter does; throw if `timedOut`.
4. `{ start, end } = monthOf(now())`, then `SELECT coalesce(sum(cost_micro_usd), 0) FROM ai_usage WHERE workspace_id = access.workspaceId AND created_at >= start AND created_at < end`. `sum` skips nulls, so a record with no reported cost adds nothing (`spend-cap-6`). Row security limits the rows to the same workspace a second time. The value comes back as text; turn it into a number and treat a result that is not a safe integer as `unavailable`.
5. Outcome: `Denied` from `withWorkspace` is rethrown (the action answers `forbidden`); the timer, or any other error, gives `unavailable`; a sum at or above the cap gives `capped`; below it gives `ok` with `charge = { workspaceId: access.workspaceId, userId: access.userId }`.

A refusal writes nothing. The check is one read: the membership query, the timeouts and the sum.

### `record`

- `withWorkspace(deps.access, headers, charge.workspaceId, "member", fn)`: the record goes through the helper too, so it is charged to the workspace the check passed, even if the session's active workspace changed during the call, and only while the person is still a member of it.
- In `fn`: the same timeouts, then one `INSERT` of every entry with `id = randomUUID()`, `workspaceId` and `userId` from `Access`, `job`, `model`, `costMicroUsd`, `currency = "USD"` and `createdAt = new Date(now())`, the time of the write (`spend-cap-2`).
- Before the insert it throws on a `costMicroUsd` that is not `null` and not a safe integer at or above 0.
- Bounded by the same `timeoutMs` timer; past it, `record` rejects.
- It logs nothing. The action logs the failure (§5).

## 5. The interpret path (`apps/web/app/directions/actions.ts`)

`run` is unchanged: the session, then the `ai-read` limit, then `fn` with the session's `activeOrganizationId`. A call the limit refuses never reaches the cap (row 11). `readBriefWithAi`'s `fn` becomes, in order:

1. `OPENROUTER_API_KEY` missing: `ai-not-configured`, as today. No database read, no record.
2. `const checked = await spendCap().check(h, workspaceId)`. `Denied` reaches `run`'s catch and becomes `forbidden` (row 10). `capped` throws `SpendCapReached`, which `run` maps to `{ ok: false, error: "ai-spend-cap", code: "AI_SPEND_CAP", retryable: false }` (row 2). `unavailable` logs `console.error("ai spend cap unavailable")` and throws `AiFailed("ai-failed")` (row 8).
3. `const calls: UsageEntry[] = []` and the adapter is built with `openRouterComplete({ ..., onCall: (c) => calls.push({ job: "interpret", model, costMicroUsd: c.costMicroUsd }) })`.
4. `interpretBrief(adapter, { text: brief })` inside `try`, with `finally { await recordUsage(h, checked.charge, calls) }`. A brief `interpretBrief` refuses before the adapter runs leaves `calls` empty, so nothing is recorded (`spend-cap-1`).
5. `recordUsage` calls `spendCap().record(...)` and never throws: on a rejection it logs `console.error("ai usage record failed", error instanceof Error ? error.name : "unknown")` and returns (row 9, open question 4).
6. The rest is today's code: a failed outcome logs its kind and throws `AiFailed`; a good one returns the sealed reading.

`apps/web/server/spend-cap.ts` (`import "server-only"`) holds the app's one helper, as `server/rate-limit.ts` holds the limiter:

```ts
let shared: SpendCap | undefined;
export function spendCap(): SpendCap {
  shared ??= createSpendCap({ access: accessDeps() });
  return shared;
}
```

No log line carries a workspace id, user id, amount, brief or key (`spend-cap-7`, row 12).

**In the studio.** `readingResult` (`read-outcome.ts`) answers `ai-spend-cap` with `{ notice: errors["ai-spend-cap"] }`, the same shape as a rate limit's notice, so the studio keeps the rules' reading, shows N1 above C1 in the note row under "Read with AI", and puts nothing in the card's notice region (row 2). `errorLine` in `i18n/wait.ts` already returns `errors[error]` for any error that is not a rate limit, so it needs no change. `SavedStudio.tsx` needs no change unless `pnpm typecheck` says so.

## 6. Two requests at once near the cap

- **No lock and no reservation.** `check` reads the records committed so far; a call's record is written after its answer. Two calls that both pass the check before either records both run.
- **Example, at the test cap of 50,000 millionths.** The sum is 49,000. Calls R1 and R2 check at the same moment, both read 49,000, both are below the cap, both call, and each records 14,000: the sum is 77,000. The next check reads 77,000 and refuses. This is row 3 with two calls in flight instead of one.
- **The bound.** A month can end above the cap by the cost of the calls that passed the check before the sum reached the cap and recorded after it, plus calls with no reported cost (spec, "Bounds", overshoot). The most one `interpret` call costs: output at most `max_tokens` 2,000 x 10 US dollars per million = 0.02 US dollars, exact from ADR 0009's price; input bounded by `BRIEF_MAX_LENGTH` (2,000 characters) plus the fixed prompt and schema, not measured, about 0.01 US dollars at an assumed 5,000 tokens. So about 0.03 US dollars a call, an estimate. A call is in flight for at most `AI_TIMEOUT_MS` (20 s), and `ai-read` lets each person start at most 10 an hour. Three members each starting 10 at once at 49,000 can add at most 30 x 0.03 = 0.90 US dollars over a 5 dollar cap. The key's own credit limit (ADR 0009 point 7) stays the outer bound.
- **Not chosen: a lock across the call.** A row lock or an advisory lock held from the check to the record holds one pooled connection for up to 20 s. The pool (`max: 5`) is shared with Better Auth and the limiter, so five readings at once would stall every request on the instance.
- **Not chosen: a reservation row.** Writing an estimate before the call and settling it after needs an `UPDATE`, which the app role does not hold (`spend-cap-7`), or a negative settling row, which breaks `cost_micro_usd >= 0` and one cost per request.
- **Revisit with the image jobs.** ADR 0018 decision 4 checks an image round's estimate against the remaining cap before the round. That check reads the same sum and has the same race; a round of four logo drafts is about 13 US cents, so the story that wires it decides whether this bound still holds.

## 7. Changed signatures

Each clause is one change a builder makes and a reviewer checks.

- **S1** `packages/intent-engine/src/openrouter.ts`: `OpenRouterOptions` gains `onCall?: (call: OpenRouterCall) => void`, with `export interface OpenRouterCall { costMicroUsd: number | null }`. `openRouterComplete` calls it exactly once for every request it sends, from a `finally` around the `fetch` and the body read, so it runs before the function returns or throws, whatever happened. **Where this differs from the spec.** It no longer does. The spec's "Tech notes" section first expected `Complete` and `openRouterComplete` to return the reported cost beside the answer text. A return value cannot carry it where the spec needs it: when `llmInterpreter` or `interpretBrief` refuses an answer (row 6), the outcome holds no adapter value, and when `openRouterComplete` throws (row 7's status 500 and aborted runs), it returns nothing. A callback from the one place that sends the request reaches both, and leaves `Complete`, `llmInterpreter` and their tests as they are. The architect chose the callback in this note; G1 and G2 passed with it under the owner's delegation (ORV-121 comment 10259, ADR 0012 decision 4), and spec v1.1 adopted it in its "Tech notes" section.
