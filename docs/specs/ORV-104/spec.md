## Why

**Guard frame (L-0012).** Every change here is to a guard rail for agents that follow the rules, not a boundary against a session that sets out to defeat it. `result-recorder`, `close-envelope.mjs`, `write-guard` and `merge-check` are deterministic text and record rules that run inside or beside the session. Nothing outside the session enforces them; the outside checks stay what they are today: the owner's approval file for a PR that changes a guard file (ORV-95), the G3 review of the diff, and, once available, GitHub rulesets (ORV-97). A bypass that only a session set on defeating a rule would type is reported once per class and goes to Honest limits, with no builder round (L-0012).

What each change allows, and what it must still block:

| 3      | The main session closes a bound envelope without `--owner` when the subagent's last hook line is an errored final stop at least 10 minutes old             | A close without `--owner` while the subagent may still run (no stop line, a sent-back stop, or a later line from the agent); a close that writes a result; any `--owner` run from a Claude Code session                                       |

The forms a rule-following agent uses, and so the forms these rules must handle (L-0012): the stories files in `packages/design-system/src/**/*.stories.tsx` (all of them declare `const meta = {...} satisfies Meta<typeof X>` and end with `export default meta;`); the spec tables in `docs/specs/*/spec.md` (headers `# | Given | When | User sees | Data effect`, `# | Given | When | Result | Evidence`, `# | Given | When | Then`, `# | Trigger | Actor | Result | ...`, and `# | Slice | Given | When | User sees | Data effect` in ORV-101); `node scripts/ovl/close-envelope.mjs <task_id>` from the ovl skill; the Write and Edit tools for the main session's doc edits.

**The four defects.** ORV-94 comment 10130 lists them (summarised in `.orivilo/handoff.md`, item 2). The evidence in the run records:

1. **Story id from the file path.** `storyTitle` (`scripts/ovl/result-recorder.mjs:137`) finds a title only in an object written after `export default`. `TaskBar.stories.tsx` declares `const meta = { title: "Application/Task bar" }` and ends with `export default meta;`, so the recorder fell back to the path title `components/task-bar/TaskBar` and asked for `components-task-bar-taskbar--*` screenshots, a story id Storybook never serves. Finding QA3-1 in `.orivilo/runs/ORV-101/ORV-101-qa-3/result.json` blocked every truthful qa approve on PR 95. The same regex runs on past `export default meta;` into the stories below it, so a story whose `args` hold `title: "..."` gives that title instead. `merge-check` imports the same function (`scripts/ovl/merge-check.mjs:13`).
2. **A slice spec not found.** `specRows` (`scripts/ovl/result-recorder.mjs:106`) reads only `docs/specs/<issue>/spec.md` and throws when it is missing. ORV-101 had no spec when `ORV-101-qa-1` and `ORV-101-qa-2` reported (fact in `.orivilo/runs/ORV-101/ORV-101-spec-1/envelope.json`); both final stops are `decision: error` in `.orivilo/heartbeat.jsonl` (lines 8019 and 8242). It also takes the fourth cell of each row as the result, which in the ORV-101 table (`# | Slice | ...`) is the When cell.
3. **Qa envelopes left open.** After those errored stops nothing closed the two background qa envelopes: no later heartbeat line names either agent, and `close-envelope.mjs` refused because it closes a bound envelope only after a `decision: allow` stop. The owner closed both with `--owner` (`closed.json` at 18:38:18Z and 19:09:40Z on 2026-10-24). A foreground call has the same gap: when judging throws at PostToolUse, the envelope stays open.
4. **Main-session `DESIGN.md` edits outside the union.** `write-guard` lets the main session edit `DESIGN.md` (its protected sets are `packages/`, `apps/`, guard files and records), while `merge-check` counts only `docs/context/handoff.md`, `docs/plans/*.md` and the issue's `jira-issue.md` as main-session docs (`scripts/ovl/merge-check.mjs:111`). The edit passes at write time and blocks the merge.

Nothing in this story is AI. Every rule is a deterministic read of files, records and hook input.

## Story

As the main session running the ovl loop, I want the recorder to read the stories files and specs the way this repo writes them, and every envelope to close when its subagent has really ended, so that a truthful qa approve is recorded, no envelope waits on the owner's terminal for a hook error, and a `DESIGN.md` edit is routed to a role before it can block a merge.

## Rules and bounds

**Story title (defect 1).** `storyTitle(root, head, file)` reads the file at `head` and finds the default export:

1. `export default <identifier>` with an optional `satisfies <Type>` or `as <Type>` and an optional `;`. The identifier must be declared in the same file as `const <identifier>` with an optional type annotation, `=`, and an object literal, which may be followed by `satisfies <Type>` or `as <Type>`.
2. `export default {` an object literal `}` with an optional `satisfies` or `as`.

The title is the `title` key at the top level of that object only, a string in `"`, `'` or a backtick with no `${`. The search never runs past the object's closing brace. When the object has no top-level `title`, the path title applies as today (Storybook's autotitle). When the default export is anything else (an imported name, a call, a spread that holds the title, a title from a variable), `storyTitle` throws `cannot read the Storybook title of <file>`. This is a text rule over the forms in the repo, not a TypeScript parser. `storyPrefix` does not change.

The recorder turns that throw into a reason in `approveProblems`, so a qa is sent back with it. `merge-check` keeps its fail-closed catch, so it exits 2.

**Spec rows (defect 2).** The spec is `docs/specs/<envelope issue>/spec.md` only; no parent or other issue's spec is read (L-0016). The table is the first one whose header row starts with `#`, as today. The result column is the first header cell equal to `User sees`, `Result` or `Then`, compared trimmed and case-insensitive. A missing file, no `#` table, no rows, or no result column is a reason (row 7, 11), never a thrown error. Each reason names the spec path.

**Closing an envelope whose subagent ended (defect 3).** The recorder closes an envelope as `no_report` whenever it knows the subagent has ended and no valid report was recorded:

- PostToolUse Agent for a foreground call (not `async_launched`) with a bound open envelope: a valid report records `result.json` (as today); reasons close it `no_report` (as today); a thrown error now also writes `closed.json` `{reason: "no_report"}` before the hook fails closed (row 12). The call has returned, so the subagent has ended.
- SubagentStop on a background stop with `stop_hook_active` true: reasons close it `no_report` (as today); a thrown error now does too (row 13).
- A thrown error at a stop with `stop_hook_active` false stays a fail-closed exit 2 that writes nothing (row 13), since Claude Code may send the subagent back.

`node scripts/ovl/close-envelope.mjs <task_id>` without `--owner` closes a bound open envelope as `abandoned` in exactly these two cases, read from `<main>/.orivilo/heartbeat.jsonl` for the envelope's `agent_id` `A`:

1. **Allowed stop (unchanged).** A line with `hook: "result-recorder"`, `event: "SubagentStop"`, `decision: "allow"` and `agent_id: A` exists. `closed.json` gets `stop: "allow"`.
2. **Errored final stop (new).** The last line whose `agent_id` is `A` has `hook: "result-recorder"`, `event: "SubagentStop"` and `decision: "error"`, and its `at` is at least 600 seconds before the script's own clock and not in the future. `closed.json` gets `stop: "error"`.

In every other case it exits 2 and `--owner`, run by the owner from a terminal outside Claude Code, stays the only way to close a bound envelope: no stop line (the session died or the subagent still runs), a last stop with `decision: block` (the subagent was sent back), any line naming `A` after an errored stop (the subagent ran again), or an errored stop under 10 minutes old. `--owner` behaves as today and writes `by: "owner"` with no `stop` field. A Claude Code session's `--owner` run stays blocked by `write-guard`. A close never writes `result.json` or `qa.json`, and a bound builder closed by any path counts as a rework round, as today (ORV-81 Rework loop step 8).

Why an errored stop with no later line is taken as final: in the records the two errored stops (lines 8019 and 8242) were the last lines of their agents, while a sent-back stop (`ORV-101-qa-3`, line 8446, `decision: block`) was followed by more lines and a recorded result. The 10-minute quiet window covers a Claude Code version that sends a subagent back after an errored stop: a subagent that works again leaves a hook line within that time on any tool call. Honest limits names the case it does not cover.

`closed.json` gains the optional field `stop` (`"allow"` or `"error"`) on a close without `--owner`. Its readers (`isOpen` in `records.mjs`, `metrics.mjs` line 225) read only presence and `reason`, so nothing else changes.

**`DESIGN.md` (defect 4).** `DESIGN.md` at a checkout's root is the design contract (`.claude/rules/design-system.md`), not a main-session doc. `write-guard` blocks the main session's Write, Edit and MultiEdit of it in the main checkout and in every worktree under `.claude/worktrees/`, judged on the resolved, lowercased path relative to the checkout (`design.md` exactly). A subagent's tool write is not judged by this rule. `docs/specs/*/design.md` and every other doc stay as they are. `merge-check`'s main-session list (`docs/context/handoff.md`, `docs/plans/*.md`, the issue's `jira-issue.md`) does not change. Bash writes of `DESIGN.md` are not judged by `write-guard` (Honest limits); no skill, agent file or AGENTS.md tells the main session to write `DESIGN.md` by Bash.

**Messages.** Stderr and stdout name task ids, agent ids, issue keys, file paths and times only; no spec or stories file content beyond the path.

**Merging this PR.** It changes guard files, so it needs `.orivilo/owner-approvals/<n>.json` for its head (ORV-95). `merge-check` runs from the develop export, so the defect 1 fix applies to merges only after this PR is on `develop`.

### Honest limits

- `storyTitle` is a text rule over the forms in the repo. A default export it does not know throws (fails closed with a clear reason); it never guesses a title. A stories file built to look like row 1 while Storybook reads another title would pass the screenshot rule with screenshots of the wrong id; the qa still looks at each screenshot.
- The errored-stop close rests on observed Claude Code behaviour (no line after an errored stop) and a 10-minute window. A subagent sent back after an errored stop that thinks for more than 10 minutes without a tool call can be closed while it runs. Its later report is then not recorded (row 20), the main session sees the work lost, and for a builder the round counts. No record is forged by it: a close writes only `abandoned`.
- A Bash write of `DESIGN.md` by the main session passes `write-guard`; `merge-check` still blocks the merge (row 24).
- Other main-session edits outside the union (an edit of a spec by the main session, for example) are still caught only at merge.

## Open questions (option, impact, default)

1. **Defect 4 direction.** A: add `DESIGN.md` to `merge-check`'s main-session docs, so the main session edits and merges it with no envelope. B: block the main session's tool writes of `DESIGN.md` in `write-guard`, so the edit goes through a designer or product envelope. Impact: A is one line and keeps today's main-session habit, but a change to the design contract then has no role record; B costs one dispatch per `DESIGN.md` edit and keeps the contract traceable. **Default: B** (rows 21 to 25). Under A, rows 21 and 24 change to: the main session's edit is allowed and `decide` gives no union reason for `DESIGN.md`.
2. **Quiet window for an errored stop.** 5, 10 or 30 minutes, or none. Impact: shorter frees the role sooner and raises the chance of closing a subagent that was sent back and still thinks. **Default: 10 minutes (600 s).**
3. **A sent-back stop with no later line.** Also let a `decision: block` last stop close after the window? Impact: covers a subagent that died after a send-back, but a send-back is the designed path where the subagent continues. **Default: no; `--owner` stays the path.**
4. **Missing spec.** A: a reason that points at L-0016 (every issue has its own spec). B: read the spec an envelope field names, which changes the envelope schema. **Default: A**, since L-0016 is promoted.
5. **No result column.** A: a reason (fail closed). B: fall back to the fourth cell, as today. **Default: A.** Every `#` table in `docs/specs/*/spec.md` today has `User sees`, `Result` or `Then`.
6. **Unreadable default export.** A: throw, so the qa is sent back and `merge-check` blocks. B: path title, as today. **Default: A**, since B asks for screenshots of an id Storybook never serves.
7. **`stop` field in `closed.json`.** Record why a close without `--owner` was allowed? Impact: one optional field; the retro can tell the two cases apart (L-0016 noted a close whose record did not say why). **Default: yes.**
