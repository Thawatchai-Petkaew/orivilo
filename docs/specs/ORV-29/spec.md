## Why

The Studio reads rows of the same shape everywhere: projects in a workspace, decisions with their reasons, versions of a profile, members of a team. E2-5 gave the canvas its unit (Card) and its overlay (Dialog); nothing yet compares rows. The handoff (§19) asks for a small table that survives Thai and Latin content, long names without spaces and missing data in both profiles, and E2-8's reference screen needs it to show long data on a small viewport. This story lands Table, the Application tier's row surface, with every §7 state as a story and a defined layout at 360 px instead of horizontal overflow.

## Story

As an agent or a person composing a Studio screen, I want Table from `@orivilo/design-system` that takes columns and rows, sorts, selects rows, shows loading, empty and error honestly, and collapses to a readable layout on a phone, so that a list of comparable records reads the same under every profile and no screen writes its own table markup.

## Rules and bounds

- **Public API.** `TableProps<Row>`: `caption` (required, the table's accessible name; `captionHidden` keeps it for assistive technology only), `columns`, `rows`, `rowKey`, `density` (`comfortable` default, `compact`), `sort`, `defaultSort`, `onSortChange`, `selectable`, `selectedKeys`, `defaultSelectedKeys`, `onSelectionChange`, `rowLabel` (names the row's checkbox), `loading`, `loadingLabel`, `empty`, `error`, `missingLabel`. `TableColumn<Row>`: `key`, `header` (a string, because it is read aloud and shown as the cell's label at 360 px), `numeric` (end-aligned mono tabular figures: digits, a unit and a sign only), `align`, `sortable`, `sortValue`, `truncate`, `width`, `cell` (a custom renderer; the default reads `row[key]`).
- **Missing data.** `null`, `undefined` and an empty string render `missingLabel` ("ไม่มีข้อมูล") in `text.tertiary`; a cell is never blank (DESIGN.md §4).
- **Sorting** is the table's own when uncontrolled and the caller's when `sort` is given; strings compare with `localeCompare` under the Thai locale, numbers numerically, missing values last in both directions. A sortable header is a real button inside the header cell, so it has a name and a focus ring.
- **Selection** is a Checkbox in the first column with a visually hidden label from `rowLabel`; the header box selects or clears every row and reads mixed when only some are selected. Selection is data, not navigation: a row is never a link.
- **Component tokens** added in `component.json`, each referencing a semantic token only: `table.bg` (`surface.card`), `border` (`border.card`), `radius` (`shape.container.radius`), `fg`, `fg-secondary`, `fg-missing` (`text.tertiary`), `header-bg` (`surface.sunken`), `header-fg` (`text.secondary`), `header-type` (`type.label.sm`), `body-type` (`type.body.sm`), `numeric-type` (`type.code.md`), `row-border` (`border.subtle`), `row-hover` (`surface.hover`), `row-selected` (`surface.selected`), `row-selected-fg` (`selection.fg`), `row-block` (`space.row-block.comfortable`), `row-block-compact`, `cell-padding-x` (`space.inset.md`), `status-padding` (`space.stack.lg`), `error` (`feedback.danger.fg`). The row divider is `border.subtle`: decorative, not floored (WCAG 1.4.11), like the other dividers in `pairs.ts`.
- **Phone layout.** The frame is a size container; under 480 px the recipe turns rows into blocks and prints each column's header before the cell through `data-label`. Explicit `table`, `rowgroup`, `row`, `columnheader` and `cell` roles keep the semantics once `display` changes (the known loss in Safari and Chrome). Nothing in the table ever scrolls sideways on its own.
- **Copy.** Thai in stories; sentence case; no middot, no em dash; the empty state invites an action; the error says what went wrong and how to fix it.
- **Stories** titled `Application/Table` so the id matches the catalog `story` field; play functions prove AC 3, 4, 5, 9.
- **Catalog status** is set to `stable` in this PR because the PR's merge is the design gate (DESIGN.md §11) and the owner's pass is the approval.

## Out of scope

Column resizing and reordering, pagination and virtual scrolling, inline editing, row expansion, a data grid with cell focus (`role="grid"`), server-driven sorting helpers, column pinning, export, Storybook docs pages, visual regression baselines.

## Depends on

E2-5 (Card ground on the canvas), E2-4 (recipes, Checkbox, Button, Badge), E2-2, E2-1, ADR 0003, DESIGN.md v1.7. Unblocks E2-7, E2-8.
