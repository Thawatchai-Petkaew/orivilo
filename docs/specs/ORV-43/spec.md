## Why

E4-2 put the board, nodes, ports and edges on screen with the keyboard as the only way to reach a command. The registry (ADR 0004 item 5) promises four more surfaces: a toolbar on the selected node, controls over the board, a context menu and a command menu, plus a sheet that lists every shortcut. Without them a pointer user cannot zoom, duplicate, group or align, and the registry has no proof that a command with a surface renders there. This story lands those surfaces, the base pieces they are made of (Kbd, DropdownMenu, ContextMenu, ToggleGroup), groups and the minimap, and the commands behind them.

## Story

As the Studio implementer, I want every E4-3 command of `catalog/commands/canvas.yaml` reachable from the surface the registry names, with the toolbar, controls, menus, groups and minimap as catalog components under the canvas tokens, so that a pointer user and a keyboard user reach the same commands and nothing on the board spells a key outside the registry.

## Rules and bounds

- **The registry is the only source.** Every surface reads `COMMANDS` filtered by its surface name and `commandAvailable` (the command's `since` is at or before `CURRENT_STORY`); nothing lists a command by hand. `surfaces.test.ts` fails when an available command with a surface is missing from that surface.
- **One runner.** The board owns `runCommand(id, context)`; the keyboard handler, the toolbar, the controls, both menus and the sheet call it. Commands the board cannot finish (`board.add-node`, `node.rename`, `board.undo`, `board.redo`, `app.toggle-mode`) go to `onCommand`; the shell says through `canUndo` and `canRedo` whether undo and redo are enabled.
- **Honest UI.** A command from a later story is not shown as available anywhere; the sheet names the story that brings it. The clipboard is in memory on the board, so the sheet and the menu say "คัดลอก" without claiming the system clipboard. The minimap is decorative; the same navigation exists in the controls.
- **Glass only where the direction allows it** (`docs/context/ui-direction.md`): the floating toolbar and controls and the command palette use `color-mix` over `toolbar.bg` with `elevation.glass.blur`; solid under `prefers-reduced-transparency`; never on a menu, a node or a dialog body.
- **Groups are nodes.** A group is a `BoardNode` with `type: "group"` and `kind: "group"`, no ports, placed before its children in the graph (React Flow's parent rule). Children keep relative positions; helpers convert to absolute positions for alignment.
- **Studio chrome.** Every new recipe reads `--cmp-*` only; the group and toolbar groups stay locked for profiles.
- **Not in this story.** The node resizer (needs the inspector to show size, E4-4), chat and task bar (E4-5), compare and history commands (E4-6), present-mode commands (E4-7), the block library and inspector panels (E4-4).

## Impact (public API, AGENTS.md rule 2)

- New exports listed in AC 1; `BoardNode` type widens to `Node<NodeContent, "orivilo" | "group">`; `NODE_KINDS` gains `group` with the word กลุ่ม; `CanvasBoardProps` gains `chrome`, `canUndo`, `canRedo`, `minimap`; `BoardContextValue` gains `selectedIds` and `run`.
- Component tokens: `kbd.*`, `command.*`, `minimap.*`, `toggle.*`, `toolbar.gap`, `toolbar.layer`, `menu.separator`, `menu.label-fg`, `menu.shortcut-fg`, `menu.option.fg-destructive`; no semantic value change; `pairs.ts` gains the new slots.
- Recipes: `ds-kbd`, `ds-menu__item`, `ds-menu__separator`, `ds-menu__label`, `ds-toggle`, `ds-toolbar`, `ds-controls`, `ds-minimap`, `ds-command`, `ds-sheet-list`, `ds-group`.
- Board: `panOnDrag` moves from right-button pan to Space and the pan tool so right-click reaches the context menu.
- Catalog: eleven entries `planned` to `stable` (Kbd moves from E4-5 to E4-3 because the menus need it), one new entry `shortcut-sheet`; `coverage.md`; DESIGN.md v1.14.
