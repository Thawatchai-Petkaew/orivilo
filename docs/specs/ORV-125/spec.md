# ORV-125: color palette per role, with its trace and the contrast proof (ORV-20 slice B)

## Why

ORV-20 slice A gives the color node its audit, its knowledge entries and its rules: a lineup and a personality vector go in, color decisions (`signature`, `neutral`, `canvas`) with their trace come out. A decision is not yet a color. This slice turns the decisions into a hex value per role and mode from curated swatch sets, carries the trace down to each role, and proves that every palette the node can produce passes the contrast contract (E0-5). The ORIVILO brand spec v1.1 §5 is the worked example it must reproduce or explain. The full reasoning, and what is real, rule-based, curated and hypothesis-grade, is in [ORV-20's Why](../ORV-20/spec.md#why); it applies here as written: no model is called, the output says `method: "rule-based"`, and hex values come from curated sets, not generated ones.

This story is ORV-20's slice B, split out so it has its own acceptance and its own PR (L-0016). It adds no requirement and no gate.

## Story

As the Intent Engine's color node, given the color decisions from slice A, I want to return a role palette for light and dark mode in which each value carries the decisions, rule ids and knowledge ids behind it, so that a person can see why every color was chosen, an open decision leaves its roles open instead of filled, and every palette the node can produce is proven readable by the existing contrast check.

## Rules and bounds

The input, the audit, the rules, the status words, the output shape and purity are ORV-20's ([Rules and bounds](../ORV-20/spec.md#rules-and-bounds)). `buildColorPalette` adds `roles` and `contractRoles` to `decideColor`'s output. The contrast proof lives in `packages/design-system`, which already depends on the engine for tests; the engine never imports the design system (ADR 0007 decision 1).

### Curated swatch sets

- One set per `signature` value holds `brand.signature`, `brand.ink`, `text.brand`, `text.link`, `text.link-hover`, `action.primary` with hover, press and disabled, `text.on-action`, `selection.bg`, `selection.fg` and `surface.selected`, each light and dark. One set per `neutral` value holds the surfaces, the remaining text roles and the borders. `canvas` selects `surface.canvas` from the neutral set (soft) or white (bright).
- The `lime` set and the `near` neutral set with `soft` canvas carry the brand spec v1.1 values wherever the spec gives them; every other value is chosen at G2 and must pass row 21.
- A role's trace is the union of the decisions that pick its set, the rules that decided them, and their `because` ids; `action.*` roles add `color.action-is-functional`.
