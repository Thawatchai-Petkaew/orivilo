# ORV-199: the sm field value sits on the centre of its box

## Goal

The sm Input, Input group, Password input and Select trigger set their value in `input.type.sm` = `type.body.sm`, 14 / 1.7. Chromium floors the top half of the leading of that 23.8 px line box, so the Thai body sits up to 1.86 px above the box centre at some box positions, outside the `ink-centre-1` bound of ORV-111 (design.md, "Measured on 4de809b" and "Cause"). The design (passed G2 under delegation, ORV-199 comment 10466) gives one fix: a single-line sm field value reads a new semantic `type.field.sm` at line height 1.6, by `field-sm-type-1` below, and Textarea sm keeps `type.body.sm`.

This spec also takes ORV-198 review finding F3 (reviewer, `ORV-198-review-1`, Suggestion): the ink-centre helper reads an Input group that holds a text addon ("THB") by the addon, so a play on it would pass on the wrong label. `ink-group-1` below closes it.

Nothing here is simulated. The readings are real Chromium screenshots at device scale 1 (Storybook test project); the token tests read the token source. The helper is a test helper, no component public API.

Why this matters to a user: a Thai value in a small field reads as floating above the middle of its box while the English value sits on it. After the fix both read centred, the box keeps its 32 px, and no Thai mark is cut.

## Rules

### field-sm-type-1

`type.field.sm` is a semantic typography token with the `fontFamily`, `fontSize`, `fontWeight` and `letterSpacing` of `type.body.sm` (`font.family.plex-sans`, `font.size.14`, `font.weight.400`, `font.letter-spacing.normal`) and `lineHeight` `font.line-height.1-6`, under every registered profile (`PROFILE_IDS`: neutral, professional, friendly). `input.type.sm` reads it. Its readers are exactly the single-line sm fields of design.md, section "Survey": Input sm, Select trigger sm, Input group sm (its input and its slots), Password input sm, and the Direction studio sample field. Textarea sm (`.ds-control[data-multiline][data-size="sm"]`) reads `type.body.sm` (ORV-192 row 18). The values come from design.md builder rows F.1 and F.2; worked example 1 gives the line box and the shift.

### field-sm-sweep-1

The play of the new Select story `LabelCentre` reads each sm trigger at the 16 box positions 0, 1/16, ..., 15/16 px below a whole CSS pixel (a wrapper `padding-top` of k/16 px, k = 0 to 15, per row), in each cell. Reason: the reading follows the fraction of the box's y (design.md, "The reading over every y"), and at the story's own y the base can pass by luck, so a play at one y can stay green on the defect (`.claude/rules/testing.md`, first rule). Expected readings over the 16 positions, from design.md row F1: Thai body -1.17 to -0.23, English 0.33 to 1.27 after the fix; Thai body down to -1.86 with `input.type.sm` on `type.body.sm` (worked example 2).

### ink-group-1

Replaces the holder choice of `ink-corner-1` clause 5 (ORV-198 spec) in `labelHolder` (`packages/design-system/src/testing/visual-asserts.ts`, ORV-198 head line 791).

1. An `<input>` passed as the box is read by its own value (unchanged).
2. A box that holds exactly one `<input>` is read by that input's value, whatever text nodes its other descendants hold (an addon such as "THB", a slot icon's title). The geometry stays the box's own, as clause 5 states.
3. A box that holds more than one `<input>` fails: `measureInkCentre` throws an error that names the box and says it holds more than one input to measure. It never picks one or falls back to the box's text.
4. A box that holds no `<input>` is read as `ink-centre-1` clause 3 reads it (unchanged).

Worked example 3 maps the cases.

## Worked examples

None is run here (no shell in this role). Each runs from the repo root with `node -e` and prints one line.

1. `field-sm-type-1`, the line box and the floored half-leading. Inputs: `font.size.14`, line heights 1.7 (`type.body.sm`) and 1.6 (`font.line-height.1-6`), the 18 px content area of IBM Plex Sans at 14 px (design.md, "Cause"). Each line: the line box (1 decimal), the half-leading (1 decimal), the part the floor drops (1 decimal); then the drop of the glyphs (1 decimal). Expected output: `23.8 2.9 0.9 | 22.4 2.2 0.2 | 0.7`.

   ```bash
   node -e 'const f=14,ca=18,r=[1.7,1.6].map(lh=>{const box=f*lh,half=(box-ca)/2;return [box.toFixed(1),half.toFixed(1),(half-Math.floor(half)).toFixed(1)]});console.log(r.map(x=>x.join(" ")).join(" | ")+" | "+((+r[0][2])-(+r[1][2])).toFixed(1))'
   ```

2. `field-sm-sweep-1`, the worst reading over every y. Inputs: over all y the Thai body covers `[c - 1, c]` and English `[c + 0.5, c + 1.5]` (design.md, "Cause"); `c` is -0.86 today and -0.23 after (the top of the Thai range in design.md, "The reading over every y" and row F1); -0.25 is the best `c`. Worst = the larger of `1 - c` and `c + 1.5`, 2 decimals with `toFixed(2)`. Expected output: `-0.86 1.86 | -0.23 1.27 | -0.25 1.25`.

   ```bash
   node -e 'console.log([-0.86,-0.23,-0.25].map(c=>c+" "+Math.max(1-c,c+1.5).toFixed(2)).join(" | "))'
   ```

3. `ink-group-1`, the holder choice. Input: a box by (text nodes outside an input, inputs held): the Input group with "THB" (1, 1), the Input group with no addon (0, 1), a Button label (1, 0), two inputs (0, 2), two inputs and text (1, 2). Expected output: `input input box throw throw`.

   ```bash
   node -e 'const h=(t,i)=>i===1?"input":i>1?"throw":"box";console.log([[1,1],[0,1],[1,0],[0,2],[1,2]].map(([t,i])=>h(t,i)).join(" "))'
   ```
