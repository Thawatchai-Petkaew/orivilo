### Why the cells that differ from tech.md differ

- **Input, Input group (addon out), Password input, Select, sm to lg, Thai and English.** The helper equals the tech.md loop on the same head in every cell (the Input family, Select body and English). Both differ from the tech.md line, and the loop on a36253b reproduces the tech.md line exactly (Table A, loop column equal to tech.md), so the base moved, not the measure. ORV-194 (merged as 4de809b, after 891fa02) changed `type.label.md` line heights from 1.5 and 1.6 to 1.7 and added `type.control.md` (git diff 891fa02 4de809b -- tokens/source), which moved the Field and the box: the tops read 47.80, 127.59 and 215.39 now against 46.39, 124.78 and 211.17 in tech.md note 3. Moving the root to the tech.md tops does not bring the tech.md numbers back (scratch run: sm -1.30, md -1.09, lg 0.11 Thai body at those tops), so the text sits on different rows in the box too; I did not isolate which token does it.
- **Select Thai ink** reads -3.80 / -4.09 / -3.89 against Input's -3.30 / -3.59 / -3.39: 0.5 px more ink above. The ORV-194 row 7 rule (`.ds-control[data-trigger] > span:first-child` pads its clip box 4 px) no longer cuts the marks. With that padding set to 0 in a scratch style, Select reads the Input values in the same run (ink -3.30 and -3.59 at sm and md; that run had the root moved to the tech.md tops, which is why they differ from Table B).
- **Tag md Thai ink** -4.00 against -3.50, the same cause: the `.ds-tag__label` rule of ORV-194 row 7. With its padding-block set to 0 in a scratch style the Tag reads -3.50, the tech.md line. The loop reads -4.00 too, so it is the base, not the cut.
- **Tag sm** has no tech.md line (tech.md reads Tag at md only).
- **Toast action**: helper -1.19 / -3.69 / 0.31, the loop and tech.md -1.50 / -4.00 / 0.00. See below.
- Button: every cell equals tech.md, loop and helper (the story sits on whole rows).

## Finding: a scope with a fractional origin shifts the reading (not tuned away)

`readGeometries` and `screenshotOf` take the screenshot's first row to lie at the scope's `getBoundingClientRect().top`. For the toast action the nearest scope that holds it is `li.ds-toast` at top 756.3125 and left 1264 (this branch), and the helper reads the whole reading 0.31 px high: -1.19 / -3.69 / 0.31. The same helper with `document.body` (origin 0, 0) as the scope reads -1.50 / -4.00 / 0.00, the loop and tech.md values, in light and dark. On a36253b the helper reads -1.48 / -3.98 / 0.02 in the same scope (its top was not read there). On this branch the shift equals the fraction of the scope's top, 0.3125, to the 2 decimals of the reading. This is the scope of clause 2 (`ink-centre-1`, shot "the way `expectEdgeInk` does") and not the corner cut; it is listed here and not changed in the rule. A play that measures the toast action should pass a scope with a whole-pixel origin (the body) until the clause is revised.
