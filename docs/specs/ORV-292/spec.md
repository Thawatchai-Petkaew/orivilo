## Story

As a founder or product owner who is signed in, I want ORIVILO to draft two or three positioning statements from what I told it about my business, each showing the words of mine it rests on, so that I can pick one, edit one, write my own or skip for now, and know that the positioning my brand starts from is one I agreed to.

## Rules this slice adds

### positioning-draft-nul-1

From v1.2. A model's answer in which any option's statement holds U+0000, anywhere, is refused whole with the clause `schema`, as an answer that breaks the answer schema of `positioning-draft-1`, and is then handled as every refused answer of that rule. The model's text is not repaired: U+0000 is not dropped from it, as it is from a person's statement (row 27). Decided under the owner's POC delegation (ADR 0012 decision 4) in ORV-292 comment 10742; the other answer is open question 1.

- **Why.** PostgreSQL `jsonb` cannot hold U+0000, and the model's statement is the one stored text the engine does not clean: such an answer passed every check of parent tech notes section 8.2 at cf00b60, and its save would fail and answer `failed` (the open point task B1 raised). The trim does not remove U+0000, which is not white space, so a statement of U+0000 alone passes the bound of 1 to 300.
- **Quotes.** A quote cannot carry U+0000 past the `quote` check, because the stored answers it must occur in have U+0000 dropped by `checkIntake` (`packages/intent-engine/src/business/intake.ts`, line 197). So the rule names statements only.
- **Not built at cf00b60.** `positioningAnswerSchema` in `packages/intent-engine/src/business/positioning-draft.ts` (line 41) holds `statement: z.string().trim().min(1).max(300)` with no U+0000 clause, and `positioning-draft.test.ts` "refused answers" holds row 13's first ten cases only.

#### Building it

- **One engine task**, write set `packages/intent-engine/src/business/positioning-draft.ts` and `positioning-draft.test.ts`. In `positioningAnswerSchema`, the option `statement` gains a refine after `.trim().min(1).max(300)` that refuses a string holding `"\u0000"`, so the refusal sits inside check 2 (`schema`), before `quote`, `basis` and `duplicate` (parent tech notes section 8.2, correction of 2026-11-19 by ORV-292-spec-3). Tests in `positioning-draft.test.ts` "refused answers": an eleventh entry of `CASES`, "a statement holding U+0000", the answer `{ options: [good("a\u0000b"), second] }` on `SHORT`, clause `schema`, with the fake model called once; the count test reads "schema six times, quote twice, basis twice, duplicate once"; the order test gains an answer whose first statement holds U+0000 and whose first option quotes words that are not in its answer, which gives `schema`. The test "the JSON Schema sent closes every object, lists the six answers and holds no bound or draft marker" stays green. Mutants, each seen red and restored, one `verified` row each: M1, the refine removed (the eleventh case is accepted); M2, U+0000 dropped from the statement in place of the refusal (the eleventh case is accepted with the statement `ab`); M3, the refusal moved after check 3 as a step of its own with the clause `schema` (the order case gives `quote`).
- **The action half**, in the B3 builder task, which owns `apps/web/app/business/positioning-actions.test.ts`: "refused answer, U+0000", with a fake model whose answer holds the statement `"a\u0000b"`: the draft action answers `ai-failed`, the usage of the one call is recorded once, no draft row exists, and no second model is called.

### positioning-draft-key-1

With no key the request answers `ai-not-configured`, consumes no `ai-read` limit, does not check the spend cap, calls no model, records no usage and stores no draft, and the step line `positioning-draft` keeps the outcome `not-configured`. With a key, draft steps 6 to 9 run as `positioning-door-1` gives them. Decided under the owner's POC delegation (ADR 0012 decision 4) in ORV-292 comment 10747; the other answer is open question 2.

- **Why.** It follows ORV-287, which put the key first for the business read in the same way and is in `develop` as 1be9506, so the two model jobs of the business board stop a request with no key at the same point.
- **Not built at 4900487.** `draftFromAnswers` in `apps/web/server/positioning-draft.ts` consumes the `ai-read` limit (line 54) and checks the spend cap (line 71) before it reads `OPENROUTER_API_KEY` (lines 83 and 84).
